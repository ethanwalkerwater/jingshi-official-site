# 教师反馈数据维护

## 当前实现

教师详情页不读取原始问卷。更新脚本在开发阶段完成清洗和聚合，只把页面需要的数据写入
`src/data/teacher-feedback.generated.ts`：

- 三项课堂偏向及各自的有效样本数
- 每位老师可公开评价的总数
- 每位老师的已匿名公开评价及评价者身份（学生 / 家长）
- 本地 DiceBear Thumbs 头像路径

当前页面首屏只展示最近 4 条评价，点击后可在弹窗中查看该老师的全部公开评价。所有教师详情页
继续采用静态生成，微信用户打开页面时不需要等待问卷接口。

最新月度 `teacher_summary` 还会生成每位官网老师的本月三项评分、有效样本数及结构化反馈主题。
月度评分作为独立记录追加，不覆盖老师的历史累计评分，也不改变名师排序。只有在历史累计数据
具备可核验的有效样本数后，才可以按样本数加权生成新的累计评分。文字摘要只识别已知的结构化
改进选项，不发布自由文本中的玩笑、乱码或个人信息。

### 更新数据

```bash
npm run data:feedback -- "/原始问卷的绝对路径.csv"
npm run data:monthly -- "/月度 teacher_summary.csv" "2026年8月"
npm run build
```

生成文件禁止手工编辑。原始 CSV 不应提交到网站仓库。

如果需要重新生成本地匿名头像池：

```bash
npm run data:avatars
```

头像下载完成后保存在 `public/avatars/thumbs`，线上页面不会向第三方头像服务发起请求。
头像样式来自 [DiceBear Thumbs](https://www.dicebear.com/styles/thumbs/)，资源内保留其 CC0 1.0
元数据。

## 计算规则

每项偏向的 `position` 范围为 0 到 100：

| 字段 | 0 侧 | 100 侧 |
|---|---|---|
| `classStyle` | 风趣幽默 | 严肃认真 |
| `teachingPace` | 高效紧凑 | 稳扎稳打 |
| `classroomInteraction` | 讲授主导型 | 互动引导型 |

计算只使用两个明确选项，`其他` 和空值不会进入分母。没有有效样本时写入 `null`，页面明确提示
样本不足，不根据教师介绍推测。

评价仅使用 `【推荐度】推荐原因`：

- 去除空白和明显无效的短文本
- 同一老师的重复文本只保留一次
- 电话、邮箱、网址和微信号自动脱敏
- 中文姓名只保留姓氏，英文姓名只保留首字母
- 根据问卷中实际填写的【学生】或【家长】专属字段标记评价者身份，不从评价文案猜测
- 首屏展示最近 4 条，全部评价通过弹窗查看，日期仅展示到月份

`Valentina 林` 和 `Valentina林` 会统一映射为网站中的 `Valentina Lin`。网站已经移除的老师不会
写入生成文件。

## 数据量增大后的长期方案

达到数百位老师或上万条评价后，不应把原始数据放进 `老师卡片.txt`、Markdown 或一个持续膨胀的
JSON 文件。建议迁移到 PostgreSQL，并把原始导出文件放在仅管理员可访问的对象存储中。

建议拆成四类数据：

1. `teachers`：稳定的教师主数据和唯一 `teacher_id`
2. `feedback_responses`：原始标准化反馈，仅后台可见，个人身份字段单独加密或哈希
3. `teacher_feedback_aggregates`：每位老师三项偏向、样本数、评分和最后更新时间
4. `public_reviews`：通过隐私检查与内容审核后可公开的评价

推荐索引：

```sql
create unique index teacher_feedback_aggregates_teacher_id
  on teacher_feedback_aggregates (teacher_id);

create index public_reviews_teacher_time
  on public_reviews (teacher_id, submitted_at desc, id desc)
  where moderation_status = 'published';
```

详情页只进行两次有界读取：

1. 按 `teacher_id` 读取一行聚合数据
2. 按时间游标读取 6 条公开评价

聚合更新可以在新问卷写入时异步执行，也可以每小时批量刷新。Next.js 页面使用静态生成或 ISR，
聚合结果进入缓存；长期方案中的“查看全部”弹窗应通过游标分页接口按需加载，不把上万条评价
写进静态页面，也不使用会随页数变慢的 offset 分页。

### 推荐的数据流程

1. 原始问卷进入私有存储
2. 定时任务校验字段、统一教师 ID、去重并做个人信息脱敏
3. 更新教师聚合表
4. 评价进入待审核状态
5. 审核通过后进入公开评价表
6. 清除对应教师页面缓存

这个结构能把公开页面、分析数据和个人信息分开，既保持固定的前台载荷，也方便后续做审核、
撤回、重新计算和数据保留期限管理。
