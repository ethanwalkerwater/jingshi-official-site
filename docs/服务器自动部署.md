# 服务器自动部署与老师数据同步

官网跑在宝塔服务器上（Next.js `next start`，前面是 nginx 和腾讯 EdgeOne）。两件事都不用再进终端：

| 改了什么 | 怎么上线 |
|---|---|
| 老师评分、课堂体验 | 不用发布。页面每小时从内部系统取一次（`getTeachers()`，`src/data/teachers.ts`） |
| 代码、老师资料、文案、图片 | 推送到 `main`（GitHub + Gitee），服务器 5 分钟内自动拉取、构建、重启 |

## 老师数据从哪来

内部系统「月度课程反馈」（`菁仕教育服务/apps/course-feedback-tracker`）每天凌晨对账答卷、每月 1 号给上上个月定稿。
接口 `GET https://app.jsjy.asia/site/teachers/stats` 只认带 `x-site-key` 的请求，返回已定稿月份的：

- 三项评分和总评分：月度分 × 当月课时加权（口径见 `教师评分数据.md`）
- 课堂体验：同一学生-老师一个月一份，按学生课时加权的偏右侧占比（0–100）

内部系统里名字和官网不同的老师在 `STATS_NAMES` 里对照（刘峥 ↔ Kevin Liu、Jack Hou）。
接口取不到时：构建阶段用 `teachers.ts` 手写的兜底分数；运行中继续显示上一次的页面。

## 服务器上的配置（一次性）

网站目录下两个不进 Git 的文件：

`.env.production.local`（Next 构建和运行都会读）：

```
TEACHER_STATS_URL=https://app.jsjy.asia/site/teachers/stats
TEACHER_STATS_KEY=<内部系统 server.env 里的 SITE_API_KEY>
```

`.deploy.env`（`scripts/auto-deploy.sh` 读）：

```
NODE_BIN=<node 所在目录>
RESTART_CMD=<重启网站的命令>
```

宝塔「计划任务」：Shell 脚本，每 5 分钟，内容 `bash <网站目录>/scripts/auto-deploy.sh >> /tmp/jingshi-site-deploy.log 2>&1`。

改了 `.env.production.local` 后手动跑一次 `bash scripts/auto-deploy.sh --force`。
